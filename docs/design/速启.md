## 一、方案与理由

速启是一个「常驻托盘 + 瞬时面板」的 Electron 桌面应用：平时完全隐藏，按 `Alt+Space` 或单击托盘图标唤出深色极简面板，按分类浏览软件、单击启动；数据存本机用户目录；随安装包分发；可开机自启动。

方案主干：

- **三层进程**：main 独占全部系统能力（热键、托盘、窗口、文件对话框、图标提取、程序启动、数据读写、自启登记）；preload 经 contextBridge 暴露最小 API；renderer 只做 UI，无任何 Node 能力。
- **核心逻辑纯化**：分类 / 条目 / 数据读写抽为不依赖 Electron 的纯 Node 模块（store.js / catalog.js），使 AC-11 的单元测试可脱离 Electron 直接 `node --test` 运行。
- **零第三方运行时依赖**：全部能力使用 Electron 内置 API；开发期依赖仅 electron 与 electron-builder 两个。
- **单窗口复用**：面板窗口启动时创建、全程复用（show/hide），不销毁重建。
- **打包**：electron-builder + NSIS，一条 `npm run dist` 产出可安装 / 可卸载的 .exe 安装器。

理由：

1. 面板是「随叫随到」的瞬时窗口 → 单窗口复用启动快、状态可控；销毁重建会引入冷启动延迟与多窗口事件竞态。
2. 失焦即藏要求窗口生命周期简单（F1.3）→ 单例窗口 + hide 语义是唯一无竞态的形态。
3. 全部系统能力收拢在 main、renderer 沙箱化 → 权限面最小；页面出错也碰不到文件系统。
4. 数据正确性可自动化验证（纯模块 + 单元测试），系统行为（热键 / 托盘 / 失焦 / 安装 / 自启）走确定性手工验收 → 验证成本与失败代价匹配。

## 二、进程结构与安全基线

### 2.1 进程分工

| 进程 | 代码位置 | 职责 | 边界 |
|---|---|---|---|
| main | src/main/*.js | 生命周期、单实例锁、热键、托盘、面板窗口、文件对话框、图标提取、启动执行、数据读写、自启登记 | 不渲染 UI |
| preload | src/preload/preload.cjs | contextBridge 暴露 window.api（唯一桥面） | 不含业务逻辑；沙箱下只能自包含单文件 |
| renderer | src/renderer/* | 面板 UI、交互、拖拽事件、toast | 无 Node、无 fs、无 ipcRenderer 裸面、无网络 |

### 2.2 面板窗口配置（window.js 常量）

```js
new BrowserWindow({
  width: 720, height: 480,
  show: false, frame: false, transparent: true, backgroundColor: '#00000000',
  resizable: false, minimizable: false, maximizable: false, fullscreenable: false,
  skipTaskbar: true, alwaysOnTop: true, hasShadow: false,
  webPreferences: {
    preload: <…/preload.cjs 绝对路径>,
    contextIsolation: true, nodeIntegration: false, sandbox: true, webSecurity: true
  }
})
```

- `skipTaskbar: true` 常开 → 面板显示 / 隐藏都不在任务栏占位（F1.3、AC-1）。
- `show: false` 且启动只建窗不显示 → F1.4「不显示常驻主窗口」。
- `transparent: true` + CSS 圆角 / 阴影实现深色极简卡片（F2.1）。
- 窗口不可缩放、不设拖拽区域（`-webkit-app-region: drag`），避免面板被误拖离屏幕。

### 2.3 安全基线（逐条结论）

1. `contextIsolation: true` + `sandbox: true` + `nodeIntegration: false`：显式声明，防未来回退。
2. preload 单文件自包含：沙箱预加载的 `require` 只能加载 electron 受限子集（contextBridge / ipcRenderer / nativeImage / webFrame / webUtils），不能加载本地文件——故 preload 不拆模块（依据：Electron 官方《Process Sandboxing》文档）。
3. 页面零远程内容：index.html 仅引用本地 css/js；CSP 取
   `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'none'`。
4. 导航与新窗拦截：`setWindowOpenHandler` 一律 deny；`will-navigate` 一律 preventDefault（同时防拖拽文件触发页面导航）。
5. IPC 最小面：仅第三节所列通道；main 对每个入参做类型校验；路径类入参在 main 侧重新校验（存在性、扩展名、判重），不信任 renderer。#18 `appIcon:get` 为无入参只读通道（读取本应用自有资产，见 4.17）——不接受 renderer 传入任何路径，故不引入新能力面。
6. 无网络：运行期零网络调用，`connect-src 'none'` 兜底。
7. 子进程面（v1.1 图标直读）：唯一外部进程调用（PowerShell）——无 shell、无字符串拼接、路径只经环境变量传递（4.8 安全节）；`windowsHide` 不产生可见窗口。

## 三、接口契约

### 3.1 IPC 通道表（renderer → main，invoke 请求 / 响应）

| # | 通道 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| 1 | state:load | — | {categories, apps, settings} | 启动时全量加载 |
| 2 | app:pick | — | {ok:true, path, defaultName} / {ok:false, code} | main 打开文件选择器（限 exe/lnk）并校验；code ∈ canceled / unsupported / duplicate / missing |
| 3 | app:validatePath | {path} | {ok:true, defaultName} / {ok:false, code} | 拖拽路径校验（code 同上） |
| 4 | app:create | {path, name, categoryId} | {ok:true, state, warning?} / {ok:false, code} | 再校验（判重）后落库 |
| 5 | app:update | {id, name, categoryId} | {ok:true, state, warning?} / {ok:false, code} | 编辑（改名 / 换分类） |
| 6 | app:delete | {id} | {ok:true, state, warning?} | 仅移除条目（F3.5） |
| 7 | app:launch | {id} | {ok:true} / {ok:false, message} | message 为中文提示（F4.3）；启动目标选择含快捷方式自愈兜底（4.9 / 4.16） |
| 8 | icon:get | {id} | {dataUrl: string \| null} | main 按 id 取完整条目，自行选择 `path` / `realPath`；payload 不增加路径，null → renderer 用占位图 |
| 9 | category:create | {name} | {ok:true, state, warning?} / {ok:false, code} | code ∈ empty |
| 10 | category:rename | {id, name} | {ok:true, state, warning?} / {ok:false, code} | code ∈ empty |
| 11 | category:delete | {id} | {ok:true, state, moved:N, warning?} / {ok:false, code} | code ∈ builtin；moved = 迁入「未分类」的条目数 |
| 12 | panel:hide | — | （send，无返回） | Esc 隐藏面板 |
| 14 | app:reorder | {id, categoryId, toIndex} | {ok:true, state, warning?} / {ok:false, code} | 条目重排与跨分类移动（F3.8 / 4.15）；categoryId = 目标分类（可异于条目当前分类）；code ∈ missing / invalid |
| 15 | hotkey:set | {accelerator} | {ok:true, accelerator, state, warning?} / {ok:false, code} | 唤起快捷键改录（F1.5 / 4.14）；code ∈ invalid / occupied |
| 16 | hotkeyWindow:close | — | （send，无返回） | 录制窗关闭（Esc / 关闭按钮，见 4.14） |
| 17 | panel:composing | {composing: boolean} | （send，无返回） | 组字态通报（compositionstart → true / compositionend → false，面板根捕获）；main 置 / 复位组字期失焦隐藏守卫（4.5 例外④）；入参非布尔 → 忽略（防御，send 通道无返回面） |
| 18 | appIcon:get | — | {dataUrl: string \| null} | 本应用图标（顶栏，F7.3 / 4.17）；无入参、只读、main 侧会话内缓存；null → renderer 隐藏顶栏图标 |

- `warning`：变更通道（#4 / #5 / #6 / #9 / #10 / #11 / #14 / #15）成功返回的可选字段，取值 `'save_failed'`——本次变更已生效于内存态、但落盘失败；renderer 收到后 toast「保存失败」（#15 经 hotkey:set 返回时显示面 = 录制窗消息行，见 4.11），并照常按 `state` 重渲染。保存类失败不走 `ok:false`（`ok:false` 仅保留校验类失败）；数据流见 3.4，持久化与重试见 4.10。
- 入参类型校验失败 → `code='invalid'`（防御分支；renderer 正常路径不产生畸形入参）。
- 实体防御码：目标实体不存在（分类 / 条目 id 未命中、编辑时目标分类不存在）→ `code='missing'`——#5 / #10 / #11 的防御分支（renderer 正常路径不产生）；与 #2 / #3 校验的 `missing`（所选 / 拖入文件不存在，文案「文件不存在」见 4.11）同码不同义。

### 3.2 main → renderer 事件

| # | 通道 | 载荷 | 说明 |
|---|---|---|---|
| 13 | panel:shown | — | 面板每次显示时发出；renderer 重置临时 UI（浮层 / 菜单 / toast / 滚动位置） |

### 3.3 preload 面（window.api）

```js
window.api = {
  loadState(), pickApp(), validateDroppedPath(path), createApp(payload),
  updateApp(payload), deleteApp(id), launchApp(id), getIcon(id),
  createCategory(name), renameCategory(payload), deleteCategory(id),
  hidePanel(), onPanelShown(cb), getDroppedFilePath(file),
  setComposing(composing),
  reorderApp(payload), setHotkey(accelerator), closeHotkeyWindow(), getAppIcon()
}
```

- `getDroppedFilePath(file)` = `webUtils.getPathForFile(file)`——拖拽取路径的唯一现行路径（Electron 已移除 File.path 属性；依据：Electron webUtils 文档）。
- renderer 拿不到 ipcRenderer 本体（preload 内包装 `onPanelShown`），通道名不泄漏到页面。
- `setComposing(composing)` = 组字态通报（send，#17）——面板根 `compositionstart` / `compositionend` 捕获调用（4.5 例外④）；无返回。
- `getAppIcon()` = 本应用图标（#18）——renderer 启动时取一次写入顶栏 `<img>` 的 src（4.17）；返回 `{dataUrl: string | null}`。

### 3.4 数据流

renderer 每次变更 → invoke → main 校验 → catalog 纯函数算出新状态 → store 落盘（失败仅 toast，不打断）→ 返回新状态 → renderer 整面板重渲染。落盘失败时，返回的 state 携带 `warning='save_failed'`：renderer 收到后 toast「保存失败」，并照常按该 state 重渲染。

单向数据流：状态在 renderer 侧只有一个副本，由调用返回值刷新；不设 main→renderer 的状态推送，避免双源同步。

## 四、机制设计

### 4.1 单实例（F4.1 / AC-10）

- main 入口阶段：先 `app.setName` / `app.setPath('userData')`（见 4.10），随即 `app.requestSingleInstanceLock()`；未获得 → `app.quit()` 并直接返回（不建窗口、不建托盘）。
- 第一实例监听 `second-instance`：若第二实例命令行含 `--autostart`（登录自启产生）→ 忽略；否则显示并聚焦面板（「唤出已有实例」）。
- 锁按取锁时刻的 userData 归并 → 开发运行、安装运行、登录自启之间，同机只有一个实例（AC-10 / AC-13 / AC-15 共用此保证；实现前提与实测点见第十三节第 5 点）。
- 初始化失败（防御）：whenReady 装配链顶层 `.catch`——console.error 留痕 + 气球「初始化失败，程序即将退出」+ 置退出中标记（使 close 拦截不把本次 quit 拦成 hide，见 4.5）→ `app.quit()`；不静默继续。

### 4.2 全局热键（F1.1 / AC-2）

- 注册来源参数化（自 v1.3 起）：`globalShortcut.register(settings.hotkey, togglePanel)`——组合串取自持久化设置（4.10 `settings.hotkey`，缺失 / 不合法归一化为默认 `Alt+Space`），ready 且托盘创建完成后执行。
- 默认 `Alt+Space` = 缺省组合语义（可改录的初始值，非固定键）；录制与改录机制见 4.14。
- toggle 语义：`win.isVisible() ? hidePanel() : showPanel()`；原生对话框打开期间忽略（见 4.5）。
- 注册状态三态（hotkey.js）：未注册 / 已注册 / 暂停——录制窗开启期间无任何注册（暂停态不持有注册，见 4.14）；关窗恢复注册按三态判定：已注册（录制期改键成功后新组合已保持注册）→ 跳过，否则按 `settings.hotkey` 注册。
- 启动注册失败（返回 false，被其他常驻程序占用）→ 不换键、不自动重试：`tray.displayBalloon` 提示「全局热键 <当前组合> 注册失败（可能被其他软件占用），可点击托盘图标唤出面板」+ console.warn；托盘路径全程可用（F1.2）。
- 退出：`will-quit` → `globalShortcut.unregisterAll()`。
- 已知取舍（键位由用户选定）：注册成功后该组合全系统由速启接管，其他应用无法再用该组合；与本机既有工具冲突则走注册失败提示路径（是否改录由用户决定）。

### 4.3 托盘（F1.2 / F1.4 / F6.2 / F7.1）

- 图标：内嵌 base64 PNG 常量（32×32 —— `#F5A623` 橙色圆角底板（1,1,31,31，圆角 r7）+ 白色闪电，外圈透明；不落资产文件 → 开发 / 打包无路径差异）；tooltip「速启」。
  - 选型理由（F7.1）：Windows 托盘区底色随系统主题在浅灰 / 深灰之间切换，透明底的单色前景必然在其中一个底色下丢失对比度 → 取「实色底板 + 高对比前景」，底板自带色块轮廓，两种底色下都立得住。
  - 闪电顶点按 32 网格重绘（笔画更粗、更短）：托盘实际渲染可小至 16px，细长笔画在该尺寸下糊成一团 → 加粗缩短，保证缩到 16px 仍是清晰可辨的闪电。
  - 形态为单版、不随系统主题换色：F7.1 与需求边界均要求「单版形态在两种托盘底色下均可辨」，运行时主题自适应不做（十一节）。
- 单击（click）→ 切换面板（与热键同一 toggle；托盘守卫见 4.5）。
- 右键菜单（setContextMenu，随状态重建）：
  - 「显示面板」→ 显示并聚焦；
  - 「开机自启动」勾选项（F6.2；勾选态 = 持久化设置；未打包运行时禁用并标注「（仅安装版可用）」，见 4.13）；
  - 「快捷键设置…」→ 打开按键录制小窗（4.14；与面板可见性无关）；
  - 「退出」→ 置退出中标记（`setQuitting(true)`）后 `app.quit()`。
- 常驻：启动即创建托盘，全生命周期常驻（F1.4）；应用无「关闭主窗口」概念。

### 4.4 面板形态与居中定位（F2.1 / F1.1）

- 形态：720×480 无边框透明卡片（深色、圆角 14px），固定尺寸，主体区内部滚动。
- 每次显示前 `positionPanel()`：`screen.getDisplayNearestPoint(screen.getCursorScreenPoint())` 取光标所在显示器 → 在该屏 `workArea` 内几何居中（x / y 取整）。多显示器与任务栏变化在下次显示时自然生效。
- 显示动画：纯 CSS（opacity 0→1、translateY 4px→0、120ms），不引入动画库。

### 4.5 显示 / 隐藏与失焦语义（F1.1 / F1.3 / AC-2 / AC-3）

- `showPanel()` = positionPanel → `win.show()` → `win.focus()`；`hidePanel()` = `win.hide()`（窗口不销毁、数据不重载）。
- 隐藏触发（按优先级）：
  1. **blur（失焦）**：窗口失去 OS 焦点即隐藏——即「点击面板外任意位置」「切到其他应用」的准确语义（F1.3）。
  2. 例外①原生对话框：main 在原生对话框期间置失焦抑制（实现形态 = `withBlurSuppressed` 计数守卫），关闭后 `win.focus()` 并复位——对话框夺焦不算「点击面板外」。
  3. 例外②托盘守卫：托盘 click 前后 300ms 内的 blur 不隐藏——防「点托盘 → blur 先隐藏 → 切换逻辑又显示」的竞态；托盘 click 依 `isVisible()` 决策（可见 → 收起；不可见 → 显示）。
  4. 例外③开发者工具：`webContents.isDevToolsOpened()` 为真时不隐藏（开发调试用）。
  5. 例外④组字期守卫（v1.3.1）：面板内文本输入处于 IME 组字期（compositionstart → compositionend）时不隐藏——输入法候选窗 / 输入法宿主抢焦点造成的假失焦不算「点击面板外 / 切到其他应用」（机制见下方「IME 组字期守卫」块）。

**IME 组字期守卫（v1.3.1 / F1.3 语义回归）**：中文等 IME 输入在组字期会出现「候选窗 / 输入法宿主抢焦点 → 面板 blur」的假失焦，按上方触发即隐藏 = 与 F1.3「点击面板外 / 切到其他应用」语义相悖（缺陷判据：按下第一个拼音键面板瞬间隐没）。

- 挂点与通报：面板根捕获 `compositionstart` / `compositionend`（自面板内任意文本输入冒泡而来）→ `api.setComposing(composing)` → IPC #17 → main 组字标记。
- 守卫范围：面板内全部文本输入——分类行内输入 + 添加 / 编辑浮层名称栏（含后续新增输入）；录制窗无文本输入、不涉及。
- 组字开始：置组字标记 → `shouldStayVisible()` 成立，blur 不隐藏（沿例外①同一守卫通道）。
- 组字结束（复位 + 焦点归属）：清除标记；窗口仍有焦点 → `win.focus()`（沿例外①「关闭后夺回焦点」形态）；无焦点且面板可见 → 不做时点判定，转入**焦点复位宽限**（下条）——隐藏判据 = 焦点宽限期内未归还才隐藏（组字结束时点的「无焦点」可能是输入法宿主尚未归还焦点、非用户切走，诊断前提即宿主抢焦点）。
- 焦点复位宽限（组字标记 + 焦点复位宽限形态；十三节实测点 14 的回退形态即本条定义）：触发 = 组字结束（`compositionend`）时窗口无焦点且面板可见；宽限时长 = 约 300ms（与例外②托盘守卫同量级；宿主归还焦点为毫秒级，真切走最多延迟约 300ms 隐藏、不构成滞留）。
- 焦点复位宽限分支与取消：宽限期内焦点归还窗口 → 取消宽限、不隐藏，命名继续（#51 / #55 绿判据达成）；期满仍未归还 → `hidePanel()`（照 F1.3 隐藏，防「组字中真切走」滞留）。宽限随任一事件取消：焦点归还 / 新组字开始（`compositionstart`）/ `showPanel()` / `hidePanel()`（与组字标记同自愈口径，见下方失败与边界）。
- 输入面配套守卫（同一组字期，防命名流程被组字按键打断）：① 组字态 keydown 不作数（`e.isComposing || e.keyCode === 229` 一律忽略——回车选词 / Esc 取消组字不误触「确认 / 取消」提交）；② 分类行内输入的「失焦 = 取消编辑」只在文档持有焦点时执行（`document.hasFocus()` 为假 = 窗口级失焦，不误取消）。
- 失败与边界：输入节点随重渲染被移除时可能收不到 `compositionend` → 组字标记不悬置（`showPanel` / `hidePanel` 均复位标记，一次隐藏 / 唤出即自愈）；组字中真移出面板 → 离开路径照旧约 300ms 隐藏（组字不进 F1.6 抑制四项，见下方边界注记）；热键 / 托盘切换语义不变（组字中 toggle 照常执行，隐藏即弃组字输入）。
- 被拒方案（逐输入挂钩 / 计数器复用 / renderer 拦截隐藏 / 焦点归属两极形态与时点判）见七节 #29 / #30；通道形态见 #31。

**鼠标离开延迟隐藏（F1.6 / AC-18）**：面板显示中鼠标移出面板且未点击，约 300ms 后自动隐藏；移出后延迟内移回则取消（不隐藏）。挂点在 renderer（面板根元素 `mouseleave` / `mouseenter` 计时，到点调 `api.hidePanel()`）；与上方 blur 路径**并存**（需求明示非替换）：

- 进入标记：`panel:shown` 重置「鼠标已进入」标记，`mouseenter` 或面板内首次 `mousemove` 置位——窗口出现在静止光标下方时不产生 enter 事件，无标记的「移出」不启动计时（抑制场景①「唤出后鼠标从未进入面板」由此成立）。
- 假移出复核（v1.3.1 / F1.6 触发语义回归）：`mouseleave` 起计前复核事件坐标——坐标仍在面板卡内（面板矩形内缩 4px 的严格内部）= 覆盖窗（IME 候选窗等）抢占命中测试造成的假移出 → 不起计；坐标在卡外或贴边 = 真移出 → 照旧起约 300ms 计时。
- 假移出复核与 `pointerOutside()`（抑制解除收尾用）的互洽关系：同一几何源（面板 `getBoundingClientRect()`）、同一问题（指针是否在面板卡内）；差别只在容差——假移出复核取内缩 4px（贴边判为面板外、走隐藏），`pointerOutside()` 取原矩形（贴边判为面板内、不起计）。边缘带的两个答案不同但无行为冲突（前者只管是否起计、后者只管抑制解除补起）。
- 误判偏向：假移出漏判（误判为真移出）→ 窄面退化为缺陷现状；真移出误判为假（事件坐标陈旧 / 偏移）→ 面板留驻至下一次 F1.3 / 真移出（可恢复）——故假移出复核取「内缩严格内」的保守判（贴边一律走隐藏）。
- 假移出复核被拒形态：`document.elementFromPoint` 命中判定（覆盖窗场景与矩形判定同信息、多一层 DOM 依赖）；把组字态加进 F1.6 抑制四项（需求确认枚举不动——组字中真移出照旧到点隐藏）。
- 抑制四项（任一成立 → 不启动或取消计时，需求枚举）：① 唤出后鼠标从未进入面板；② 添加 / 编辑浮层或面板内菜单打开中（含行内确认，按 components.js 打开态统一判定）；③ 条目拖动排序中（4.15）；④ 原生文件对话框打开中（「＋」`pickApp` 在途）。
- 抑制解除收尾：任一抑制结束（拖动结束含取消 / 原生文件对话框关闭 / 浮层与行内确认关闭）且指针已在面板外 → 补起 300ms 隐藏计时（到点隐藏、延迟内移回取消——与 F1.6「约 300ms 隐藏、移回不隐」语义对齐，不取直接隐藏）；计时由抑制解除事件起算，不依赖补发 `mouseleave`（拖动态吞掉的 leave 不再重发；边界事件送达序见十三节实测点 13）。
- 与 blur 的优先级：blur 立即隐藏优先；计时到点时若已隐藏，`hidePanel()` 幂等无操作（window.js 既有语义不变）。
- 与 4.5 例外①②③④ 的关系：四类例外只作用于 blur 隐藏路径；鼠标离开路径的抑制由上列四项独立判定（对话框场景两侧同时成立、行为一致；DevTools 例外③、组字期例外④均不扩展到本路径——抑制枚举按需求四项执行）。
- 边界注记：分类行内输入中移出面板不属抑制四项 → 到点隐藏、输入随隐藏丢弃（与「隐藏即弃临时态」及 F1.3 点外丢失的既有语义一致，不扩展枚举）。

- 再唤起聚焦：`show() + focus()` 为主动作；若遇 Windows 前台锁未夺焦（实现期实测确认），回退 `setAlwaysOnTop(false → true)` 触发置顶刷新。
- 关闭拦截：窗口 `close` 事件一律 `preventDefault + hide`（Alt+F4 / Ctrl+W 不退出应用）；退出唯一入口 = 托盘「退出」。
- 键盘：Esc = 有浮层先关浮层（表单 / 菜单），否则发 `panel:hide`。

### 4.6 面板 UI 与交互（F2.2～F2.5 / F3.2 / F3.4 / F3.5 / F4.4）

布局（深色极简，自上而下：顶栏 → 分类标签页栏 → 当前分类内容区）：

│   [图标] …                                      │
└────────────────────────────────────────────────┘
（当前分类为空：内容区显示虚线占位「拖入软件到此分类」；
 全部软件为空：内容区替换为「点击「+」添加软件」+ 副行「或将 .exe / .lnk 拖入窗口」）

- 分类标签页栏：顶栏下方单行横向；顺序 = 分类数组顺序（创建顺序，「未分类」恒在首位）；末尾「＋ 新建分类」幽灵按钮。
- 选中态：活动标签文字 `#e8eaed` + 底部 2px `#4c8dff` 指示条；非活动标签 `#9aa0a6`（hover 底 `rgba(255,255,255,0.06)`）；点击标签即切换（F2.2）；悬停切换见下块（F2.6）；内容区只渲染该分类的条目。

**悬停切换标签（F2.6 / AC-19）**：鼠标在非活动分类标签上停留约 200ms 即切换到该标签页，内容区同步；

- 计时与取消：`mouseenter` 标签起 200ms 计时，`mouseleave` 取消；移到另一标签重新起计——快速扫过多个标签不切换；悬停活动标签 = 无操作。
- 抑制：条目拖动排序中不触发（4.15 抑制标记）；分类行内输入中不切换（沿「行内输入期间忽略标签操作」既有规则）；浮层 / 行内确认打开中不切换（防打断模态操作，UI 决策见十二节）。外部 .exe / .lnk 拖入经过标签栏同样不触发——依赖「HTML5 拖放期间不产生鼠标 enter 事件」这一事件送达前提（待实测点 12）；前提不成立 → 置显式「拖入中」抑制标记（`dragover` 置位、`drop` / `dragend` 复位），悬停切换读该标记抑制（防拖经标签栏切标签、致 4.7 分类预选静默变类）。
- 触发语义：到点先收起面板内菜单（沿「点外收起」语义）再切换；切换动作复用 `switchCategory`（点击路径同一函数，行为一致）。
- 失败与边界：标签栏横向滚动中悬停到滚入视野的标签同样计时；切换失败（目标分类不存在）按既有守卫静默忽略。
- 多标签溢出：标签栏不换行，超出面板宽度时横向滚动（滚动条隐藏，滚轮映射为横向滚动）；切换 / 新建 / 重命名后 `scrollIntoView` 保证活动标签与「＋ 新建分类」可见。
- 活动标签：会话内状态（不落盘）；默认 = 默认分类（固定 id `uncategorized`）；面板隐藏再唤出不重置，重启应用回默认分类。添加 / 编辑落库后切到该条目所属分类；删除当前分类后切回默认分类。以上默认 / 回退 / 切换三类位置均按固定 id 引用——默认分类改名后，其显示取当前名。

### 4.7 添加流程与拖拽（F3.1 / F3.6 / AC-4 / AC-5）

两条入口收敛到同一「校验 → 浮层 → 落库」：

- 「＋ 添加软件」→ main `dialog.showOpenDialog(win, {properties:['openFile'], filters:[{name:'程序', extensions:['exe','lnk']}]})`（期间抑制失焦隐藏）→ 校验 → 打开添加浮层（预填）。
- 拖拽：renderer `dragover` / `drop` preventDefault（防导航）→ 取 `files[0]` → `api.getDroppedFilePath(file)` → `app:validatePath` 校验 → 打开浮层（分类预选 = 当前活动标签页对应分类；不区分面板内拖放位置）。多文件拖入取第一个，其余忽略（toast「本次仅添加 1 个」）。
- 统一校验（main 侧，对所有路径入参）：存在；扩展名 ∈ {.exe, .lnk}（大小写不敏感）；判重 = 规范化路径（`path.resolve` + 小写化）对现有条目比较 → 命中 code = duplicate → toast「已存在」（F3.6，提示语固定）。
- 落库（app:create）再判重（防两次拖拽竞态）；条目为 .lnk 时同时解析并登记其真实目标 `realPath`（F3.9 / 4.16；解析失败不影响落库）；成功 → 活动标签切到该条目所属分类（见 4.6）；名称 trim 后为空 → 提示并停留浮层。

### 4.8 图标与容错（F3.2 / F3.7 / F3.10 / AC-4 / AC-16 / AC-24）

- 常规路径：`app.getFileIcon(path, {size:'large'})`（Windows large = 32px）→ `toDataURL()` 字符串走 IPC（避免 NativeImage 跨进程序列化差异）。
- 缓存分两层，均为会话内存且含失败结果：条目结果缓存键 = 规范化后的 `entry.path`；来源结果缓存键 = 规范化后的实际取图来源。规范化统一为 `path.resolve` + 小写化。重启后重取，图标不落盘、不改目标文件。
- 取不到图标 → renderer 用 CSS 首字符圆角块占位（零资产）。判定与回退全在 main 侧——renderer 与 IPC 契约（#8 通道）不变。

**触发判定（F3.7「返回系统通用图或失败」的精准识别）**：PNG 字节级比对；参照物来自同一 `getFileIcon` 管道、懒加载（首次取图标时构造一次，会话内复用；并发请求合并到同一 Promise）。

- refExe（通用 exe 图）：临时目录写 0 字节 `ref.exe` → getFileIcon → `toPNG()`。
- refLnk（通用快捷图）：`shell.writeShortcutLink` 建临时 `ref.lnk`（指向 ref.exe）→ getFileIcon → `toPNG()`。
- 判定：候选与任一参照字节相等 → 「系统通用图」；平台结果为空（isEmpty）同样判失灵。

实测依据（探针 v8，`.thincoder/tmp/iconprobe/probe-lnk.cjs`）：DSH 平台结果 == refExe（538B、32×32）；lnk→DSH 与两个临时 .lnk（目标有效 / 目标缺失）三者同为 557B 且互相字节相等——.lnk 的平台结果与目标无关，须用 refLnk 识别；参照物置于 %TEMP% 与置于项目盘结果等值。

**直读兜底（触发后执行）**：选中路线 = PowerShell 小助手（选型与备选见第七节 #13 / #15）。

- 调用：`powershell.exe -NoProfile -NonInteractive -EncodedCommand <脚本 base64>`；路径与输出经环境变量 `SUQI_ICON_SRC` / `SUQI_ICON_OUT` 传递。
- 脚本（代码内常量，无拼接）：`[System.Drawing.Icon]::ExtractAssociatedIcon($env:SUQI_ICON_SRC)` → `ToBitmap().Save($env:SUQI_ICON_OUT, Png)`；成功 exit 0，异常 catch → exit 1。
- 实测：exit 0、32×32 PNG 2229B（与既有 System.Drawing 直存字节一致、跨调用稳定）；单次 0.16–0.23s；文件不存在 → exit 1、无输出文件。
- 成功判定 = 退出码 0 + 输出文件存在 + nativeImage 非空；不依据 stderr（实测成功调用也写 CLIXML 进度噪音）。
- 在途并合分两层：来源加载按规范化路径键在 Promise 创建时入缓存，先后 / 并发的等价来源只进入一次平台判定与直读；直读低层仍按传入路径串并合，作为同一来源任务内部的重复保护。两层都不并行启动同一来源的子进程。

**兜底链（含 .lnk 条目链）**：原则 = 非通用结果一律保留；触发后按序取第一个「非通用」结果，全失败则维持现有表现。平台对任何 .lnk（含 IconLocation 自定义图标的 .lnk）恒返回通用快捷图（实现期实测 2026-10-06；见第十三节第 7 点）。自定义图标快捷方式仍按目标真图标处理，不新增 IconLocation 判据（被拒理由见决策 #17）。

- 来源选择由 4.16 的 `pickIconSource` 单点定义；本节只定义「选定来源后如何取图」。原条目路径的平台结果先保留为既有表现，再进入来源链。
- `.exe` 条目：来源 = `entry.path`；① 来源平台图标；② 命中 refExe / refLnk 或平台结果为空时直读来源；③ 来源平台结果 / null。
- `.lnk` 条目仍在盘上且解析出非空 target：来源 = target；① 目标平台图标；② 直读目标；③ 原 .lnk 平台结果优先、目标平台结果次之 / null。该分支与 v1.1 行为相同。
- `.lnk` 条目路径不存在，或路径存在但解析抛错 / 无 target，且 `realPath` 非空：来源 = `realPath`；① 来源平台图标；② 命中参照或平台结果为空时直读来源；③ 只回到原 .lnk 的平台结果 / null。来源自身的通用平台图不替换原表现。
- 来源结果用 `{resolvedDataUrl, platformDataUrl}` 表达：`resolvedDataUrl` 只装「非通用平台图、直读真图，或参照物全失效时按 F3.7 保留的平台结果（仅 direct 分支——来源即条目路径，保留值与第③级同义；其余分支全失效时不装保留值，收口见 4.16）」；最终降级顺序由上列分支决定，不能把来源通用图误当自愈成功。
- 来源结果缓存保存上述结构，不掺条目专属的第③级降级；因此失效 .lnk 与同目标 .exe 条目以同一规范化来源键复用一次平台判定 / 直读，先后或并发请求都不重复起子进程。条目结果缓存再按各自 `entry.path` 保存最终 dataUrl / null。
- 缓存 Promise 在加载开始即入来源表，成功、降级与 null 均缓存；`createIconSourceCache` 负责先后与并发复用。既有直读串行队列仍限制同一时刻至多一个 PowerShell 进程。
- **嵌套 .lnk（来源本身是 .lnk）**：不再次调用 `pickIconSource`，只把该路径作为一次平台 / 参照 / 直读来源；不递归解析下一层。失败后按所属分支的第③级降级，沿用既有边界。
- 「直读也取不到」判定：直读输出与「直读 ref.exe」输出字节相等 → 视为仍是通用图、不当作取到（参照 refDirect 懒加载，首次直读前一次调用）。

**失败处理与降级**：参照物取不到 / PowerShell 不可用 / 调用超时（10s → kill 子进程）/ 输出文件缺失或不可解码 / 临时文件读写失败 → 仅影响该条目（维持现有表现），其余条目不受影响，`console.warn` 留痕；参照物单侧失败（仅 refExe 或仅 refLnk 取不到）→ 该类条目的触发判定收窄（缺 refExe → .exe 条目；缺 refLnk → .lnk 条目），该类行为等同现状、不波及另一类（空结果判定不受影响）；参照物全部获取失败 → 判定整体不触发（行为等同现状、不报错）。

**性能与时延预算**：常规程序 = 原路径 + 每图标一次字节比对（微秒级）+ 参照物一次性构造（毫秒级）；失灵程序 = 每个 ≈0.2s，直读经会话内串行队列（同一时刻至多一个 PowerShell 进程）。首次打开含 k 个失灵条目的分类：最坏 k×0.2s（实测机 k=1），图标逐个异步补入（沿用 renderer「占位 → 原位替换」），面板不阻塞。超时情形（10s 口径）：单条超时 → 等待期间该条目保持占位、面板可继续操作；串行下最坏上界 ≈ k×10s（队首超时推迟后续条目补入）；超时结果按失败缓存——该路径会话内不再重试。

**安全（子进程与临时文件）**：

- 无 shell、无字符串拼接：候选路径只经环境变量传递（数据通道），脚本为代码内常量经 base64——任何候选路径（含快捷方式目标）都进不了被解析的命令文本，无注入面。
- `-NoProfile -NonInteractive`（不加载用户配置、不交互）；`windowsHide: true`（不闪控制台窗）。
- 临时物：会话级目录（`os.tmpdir()` 下 `suqi-icons-XXXX`，`mkdtemp` 独占创建）——`out.png` 每次读取后即删；`ref.exe` / `ref.lnk` 会话内保留；`will-quit` 整目录清理（尽力而为，失败仅留痕）；不写目标文件所在目录。
- 结论：仍不需要任何图标提取第三方库——内置能力 + Windows 自带 PowerShell 直读覆盖 exe / lnk 人工样本；运行时依赖保持零第三方（PowerShell 5.1 为 Win10/11 系统组件）。

### 4.9 启动执行与失败检测（F3.3 / F4.3 / F3.9 / AC-4 / AC-8 / AC-22）

- 采用 `shell.openPath(path)`：走 Windows ShellExecute，.exe 与 .lnk 统一处理（.lnk 由系统解析目标）；返回 Promise<string>，成功为 `''`，失败为错误信息（依据：Electron shell 文档）。
- 启动目标选择（三级，F3.9 自愈）：① 条目路径存在 → 按条目路径启动；② 条目路径不存在且为 .lnk 条目、其登记的 `realPath` 存在 → 按 `realPath` 启动（用户无感，见 4.16）；③ 两者都不存在 / 不可用 → 「启动失败：目标文件不存在」（4.11 固定文案，不发起 openPath）。
- 失败检测两道：① 上列目标选择落第③级 → 「启动失败：目标文件不存在」（AC-8 场景）；② openPath 返回非空 → 「启动失败：无法启动该程序」（原始信息记 console）。
- 成功 → renderer 收到 ok 后立即 `hidePanel()`（F3.3 单击启动 + 收起）；失败 → 面板留驻并 toast（F4.3 不静默）。
- 不采用 `spawn`：.lnk 无法直接执行（需自行解析目标与参数），且 openPath 的错误信息更贴近用户可读（被拒方案见第七节）。
- 安全：不拼接用户输入参数、不启用 shell、路径仅来自已录入条目（含其登记的 `realPath`）。

### 4.10 数据模型与持久化（F4.2 / AC-6 / AC-9）

- 路径：ready 前 `app.setName('速启')` + `app.setPath('userData', join(app.getPath('appData'), '速启'))` → 数据文件 `%APPDATA%\速启\data.json`；**开发运行与安装运行同一路径**（AC-13 一致性、F5.3 数据保留、F6 自启登记共用的前提）。AC-9 的「具体路径」即此。
- 注入接缝（store 可脱离 Electron 运行）：store.js 以「基础目录」为入参——由 main 注入（ready 前完成 setName / setPath('userData') 后取 userData 路径传入）；自身不引用 Electron，数据文件 = `<基础目录>/data.json`。单元测试以 `fs.mkdtemp` 临时目录作为基础目录、用例收尾删除——不触碰真实 `%APPDATA%\速启`。
- 结构（version 1；可读 JSON、UTF-8、2 空格缩进）：

```json
{
  "version": 1,
  "categories": [
    { "id": "uncategorized", "name": "未分类", "builtin": true },
    { "id": "c-3f2a…", "name": "开发", "builtin": false }
  ],
  "apps": [
    { "id": "a-9b1c…", "name": "VS Code", "path": "C:\\…\\Code.exe",
      "categoryId": "c-3f2a…", "addedAt": "2026-10-06T11:00:00.000Z",
      "realPath": null }
  ],
  "settings": { "autoLaunch": true, "hotkey": "Alt+Space" }
}
```

- id：`crypto.randomUUID()`（Node 内置）；「未分类」固定 id `uncategorized`（恒首位、不可删；名称可改——初始「未分类」，规则见下行）；`settings` 是 F4.2「设置」与 F6.2 自启状态的落点。
- `realPath`（v1.4 / F3.9）：条目为 .lnk 时登记其指向的真实程序位置，非 .lnk 或未解析到 → `null`（可选字段，缺省 null；采集与自愈见 4.16）。
- 规则（catalog.js，纯逻辑）：未分类不可删、可改名（改名仅改 name——id / builtin / 恒首位不变；名称 trim 后空拒绝；重名允许）；删除分类 → 其下条目 categoryId 改写为 uncategorized（迁移目标按固定 id，与显示名无关；返回 moved 数）；新增判重按规范化路径；分类与条目顺序 = 数组顺序（条目顺序调整与跨分类移动 = apps 数组内重排，4.15）。
- 载入（store.js）：缺文件 → 立即写默认结构（首次运行即满足 AC-9）；解析失败 → 原文件改名 `data.corrupt-<时间戳>.json` + 默认结构启动；version 高于当前 → 备份 `data.backup-<时间戳>.json` + 默认结构（不覆盖可疑数据）。
- 载入归一化（字段级）：缺失字段补默认（`realPath` 缺失 / 非字符串 / trim 后为空 → `null`）；条目指向不存在分类 → 落「未分类」（按固定 id）；「未分类」名称取存储值（缺失 / trim 后为空 → 初始名「未分类」；非空取 trim 后值——与改名路径「名称 trim 后生效」同口径）；写回采用白名单字段（含 `realPath`）。
- 数据版本（v1.4）：`DATA_VERSION` 保持 1——`realPath` 以可选字段方式增量引入（决策 #40）；载入后 main 侧对存量 .lnk 条目做一次 `realPath` 补登记（4.16），补到即落盘（失败仅 console.warn，不打断启动）。
- 设置归一化（载入侧）：`settings.hotkey` 缺失 / 空白 / 不含修饰键 / 键名不可识别 → 默认 `Alt+Space`；合法值 trim 后保留（判定与归一化规则见 accelerator.js 纯逻辑，4.14）。
- 保存：每次变更同步「写 `data.json.tmp` → `fs.renameSync` 原子替换」；失败 → 保留内存态 + 对应变更通道返回的 `state` 带 `warning='save_failed'`（renderer toast「保存失败」），下次变更重试。
- 并发：单实例 + 单窗口 → 无并发写路径。

### 4.11 消息提示（F4.3 / F4.4 / F3.6）

- 面板底部单条 toast：常规 3s、错误 5s 自动消失；新消息顶替旧消息。
- 文案表（固定）：已添加 / 已存在 / 已移除 / 保存失败 / 启动失败：目标文件不存在 / 启动失败：无法启动该程序 / 仅支持 .exe / .lnk 文件 / 文件不存在 / 分类名不能为空 / 软件名不能为空 / 本次仅添加 1 个 / 快捷键须含 Ctrl / Alt / Shift / Win 之一 / 不支持的按键。
- 「文件不存在」用于添加 / 拖拽校验（#2 / #3）的 `missing` 码（所选或拖入的文件不存在）；启动路径的同类失败文案为「启动失败：目标文件不存在」（4.9）。
- 录制窗显示面（v1.3）：「快捷键须含 Ctrl / Alt / Shift / Win 之一」「不支持的按键」两枚文案的显示面 = 录制窗提示行兼消息行（4.14），不经面板 toast；「保存失败」经 hotkey:set（#15）返回 `warning` 时同样显示于录制窗消息行，其余变更通道仍走面板 toast。

### 4.12 打包与安装（F5 / F7.2 / AC-12～AC-14 / AC-21）

- 选型：**electron-builder**（实测最新 26.15.3，2026-10-06 经镜像查询）+ NSIS 目标。理由：一条命令产出 .exe 安装器；NSIS 原生支持「可自选安装目录」「桌面 / 开始菜单快捷方式」「卸载器」；本项目零运行时依赖，不受打包器约束。
- 配置落点：项目根 `electron-builder.yml`（与 package.json 分离，保持可读）。
- 产出目录：`dist/`；产物 `Suqi-Setup-<version>.exe`（ASCII 文件名规避编码问题；应用显示名仍为「速启」）。
- 关键配置（意如表；键名以 electron-builder NSIS 配置为准，首次构建由 schema 校验）：
  - `appId: io.thincoder.suqi`、`productName: 速启`、`directories.output: dist`、`files: src/**/* + package.json`（docs/、批次档、node_modules 不入包）。
  - `win.icon: build/icon.ico`；`nsis.installerIcon` / `nsis.uninstallerIcon` 同指该文件（F7.2；见本节末「应用图标」条）。
  - `win.target: nsis`（x64）；`nsis.oneClick: false` + `allowToChangeInstallationDirectory: true`（F5.2「可选安装目录」）。
  - `nsis.perMachine: false`（按用户安装，免管理员）；`createDesktopShortcut` / `createStartMenuShortcut: true`、`shortcutName: 速启`。
  - `nsis.deleteAppDataOnUninstall: false`（F5.3：卸载保留用户数据；用户数据本就在安装目录之外）。
  - `artifactName: Suqi-Setup-${version}.exe`；`publish: null`（不做发布 / 自动更新）。
- 命令：`npm run dist` = `electron-builder --win nsis --publish never`（F5.1「一条命令」，可重复——同名产物覆盖重建）。scripts 全集：`start`（electron .）/ `dist` / `test:unit`（见第八节）。
- 卸载清理（F5.3 的完整形态）：`build/installer.nsh`（`nsis.include`）的 `customUnInstall` 宏枚举 `HKCU\…\Run`，删除数据指向本安装目录（`$INSTDIR`）的值——与登记值名无关，不误删其他软件的自启项。防「卸载后残留死链自启项」。
- 无代码签名（边界已列）：不配证书 → 首装可能有 SmartScreen 提示（用户已接受）；构建输出无签名警告属预期。
- 一致性（AC-13）：安装版与开发版同一 src、同一 userData 路径 → 功能与数据一致；单实例锁跨二者生效。
- 构建期环境：默认 npm registry 实测不可用（registry.npmjs.org 连接超时），需用镜像 `--registry=https://registry.npmmirror.com`（实测可用）；electron 二进制与 electron-builder 的 NSIS / 签名工具首次构建需下载，若直连受限需设 `ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR` 指向 npmmirror 镜像。运行期无网络需求不变。
- 应用图标（F7.2）：`build/icon.ico`（ICO 容器 7 档齐：16×16 / 24×24 / 32×32 / 48×48 / 64×64 / 128×128 / 256×256，103,887 字节）；`win.icon` + `nsis.installerIcon` + `nsis.uninstallerIcon` 三处均指向它 → 安装后的 exe / 开始菜单 / 桌面快捷方式、安装器与卸载器统一显示本应用自带图标。形态与托盘图标同源（橙色圆角底板 + 白闪电，见 4.3）；该文件为本工程首个二进制资产（6.5），生成方式见决策 #34。

### 4.13 开机自启动（F6 / AC-15）

- 落点：main 的独立模块 `src/main/autolaunch.js`（封装 Electron 登录项 API）；状态存 `settings.autoLaunch`（默认 true，F6.2）；托盘勾选项读写该状态。
- 登记 / 取消：`app.setLoginItemSettings({ openAtLogin: enabled, path: process.execPath, args: ['--autostart'] })`；随后 `app.getLoginItemSettings({ path, args })` 读回校验，不一致 → 托盘气球提示「开机自启动设置未生效」。
- 状态同步（两侧一致）：
  - 启动时（仅打包版）reconcile：读 `settings.autoLaunch` → 与系统状态比对 → 不一致则按设置登记 / 去除（自愈：安装路径变化、外部误删等）。
  - 托盘勾选变更：先写设置落盘 → 再 apply → 重建托盘菜单勾选态；两条失败路径均保留用户意图值并气球提示——落盘失败 →「开机自启动设置未保存」（store 先更内存态、后落盘）；apply 失败 →「开机自启动设置未生效」。
- 开发运行 vs 打包运行（结论）：**仅打包版登记自启**（`app.isPackaged` 门槛）；开发运行下托盘该项禁用并标注「（仅安装版可用）」，不写注册表。
  - 依据：需求 F6.1 明示「作用对象为已安装版本」；开发机无需被登录拉起。
  - 技术上开发运行亦可支持（path = electron.exe + args = 项目目录），设计不取——避免与开发调试互相干扰。
- 登录启动行为：注册命令带 `--autostart`；应用启动后照常常驻托盘、面板不弹出（F1.4）；若登录时已有实例在跑（罕见竞态）→ 第二实例因 `--autostart` 不唤出面板（4.1）。
- 与卸载的关系：卸载时 `customUnInstall` 删除自启登记（4.12）；重装后首次运行按持久化设置（默认开启）重新登记 → F5.3 与 F6.2 自洽。

### 4.14 自定义唤起快捷键（F1.5 / AC-17）

方案（入口 → 录制 → 注册替换 → 持久化）：

- 入口：托盘右键菜单「快捷键设置…」（4.3）→ 打开按键录制小窗。窗体 = 独立瞬态小窗（决策 #22）：`src/main/settings-window.js`（生命周期）+ `src/renderer/hotkey.html` / `hotkey-window.js`（录制 UI），复用 preload 与 styles.css；360×160 无边框、skipTaskbar、置顶、居中于光标所在屏；单例（重复打开 = 聚焦既有窗）。
- 录制窗内容与交互：显示当前组合（读 `settings.hotkey`）+ 提示行「按下新的组合…」（兼消息行——拒绝 / 落盘失败文案就地显示，见下「拒绝与归一化」与「失败与边界路径」）；按下合法组合即录入（无候选态 / 无确认按钮；仅修饰键按下不算组合、继续等待）；「关闭」按钮 / Esc = 关闭且不产生变更。
- 录制期热键暂停：录制窗打开 → main 注销当前注册（三态置「暂停」，4.2）——录制窗开启期间无任何注册，旧组合暂停、不可唤出（仅托盘可用）；暂停原因 = 已注册组合会被 RegisterHotKey 吞掉、录不进录制窗（含「录回当前组合」场景）。关闭 → 按三态判定恢复注册（4.2）：已注册（录制期改键成功后新组合已保持注册）→ 跳过重注册，否则按 `settings.hotkey` 注册（失败照 4.2 气球）。
- 组合合法性（accelerator.js 纯逻辑，决策 #26）：须含 Ctrl / Alt / Shift / Win（→ Electron `Super`）之一；键位 ∈ 白名单（字母 / 数字 / `F1`–`F24` / `Space` / `Tab` / `Enter` / 方向 / `Home` / `End` / `PageUp` / `PageDown` / `Insert` / `Delete` / 常用标点）。
- 拒绝与归一化：无修饰键（如 `F5`）→ 录制窗提示行显示「快捷键须含 Ctrl / Alt / Shift / Win 之一」；键名不可识别 → 提示行显示「不支持的按键」——两枚文案显示面 = 录制窗提示行兼消息行（非面板 toast：录制窗打开时面板已随失焦隐藏，面板 toast 不可见）；下一次 keydown 恢复提示语「按下新的组合…」；组合串归一化（修饰键序 Ctrl+Alt+Shift+Super、字母大写）。
- 注册替换（`hotkey:set` #15，决策 #24）：组合有变化时先注册新组合、成功再注销旧组合——该顺序只对存在活跃注册的状态成立（「已注册」态下旧组合在替换全程可用；录制期为「暂停」态、无活跃注册，「注销旧组合」为空操作）；新 = 旧 → 短路「无变化」直接 ok（组合未变，不重复注册）。
- 成功路径：新组合注册成功 → 更新 `settings.hotkey` 并落盘（4.10）→ 注销旧组合（暂停态下为空操作）→ 托盘气球「唤起快捷键已更新为 <组合>」→ 录制窗自动关闭；新组合保持注册，关窗恢复注册按三态判定跳过重注册（4.2）。
- 失败与边界路径：新组合注册失败（返回 false / 抛错，被占用）→ settings 不变、旧组合保留（关窗恢复注册后仍生效）、托盘气球「快捷键 <组合> 注册失败（可能被其他软件占用），已保留原快捷键」、录制窗留开可重试；落盘失败 → `warning='save_failed'`（3.1 语义）：新组合已生效于内存态、录制窗消息行显示「保存失败」且窗口留开（消息须可见可观测，不随「已生效」自动关闭），重启后回旧组合（与既有 warning 语义一致）。
- 与既有机制的关系：4.2 注册来源参数化 + 三态；录制窗与面板可见性无关（面板若显示，点托盘菜单后按 F1.3 随失焦隐藏属预期）；录制窗不参与 F1.6 鼠标离开隐藏（那是面板路径）；退出时 `unregisterAll` 不变。
- 边界：不做「恢复默认」专门入口（重录 `Alt+Space` 即回默认）；不做组合冲突预检测（以注册成败为准）；不做多套方案切换。

### 4.15 拖动排序与跨分类移动（F3.8 / AC-20）

方案（数据落点 → 逻辑面 → 交互 → 落位与取消）：

- 数据落点（决策 #23）：**apps 数组重排**（不设序号字段）——顺序语义沿 4.10「顺序 = 数组顺序」；同分类重排 = 从 apps 抽出该条目、插到目标邻位；跨分类移动 = 抽出后改写 `categoryId` 再插到目标分类的落位，其余条目相对顺序不变（目标分类外的条目不受扰动）。持久化 = 既有 `store.save` 全量写；无 schema 变更、data version 仍为 1。
- 逻辑面（catalog.js 纯函数）：`reorderApp(state, {id, categoryId, toIndex})`——`categoryId` = **目标分类**（可异于条目当前分类），`toIndex` = **落位序位**（0 起的最终下标；落位后该条目在目标分类条目序列中的下标）。值域按两情形分别界定：同分类重排 = 0..该分类条目数 - 1（该分类含被拖条目）；跨分类移动 = 0..目标分类当前条目数（目标分类不含被拖条目，故其上界 = 其当前条目数）。
  - 值域展开：目标分类为空 → 0（唯一）；同分类追加末尾 → 该分类条目数 - 1；跨类追加末尾 → 目标分类当前条目数。**两情形合法上界不同（同分类 = 长度 - 1、跨类 = 目标分类当前条目数），这是正常的，不得写成「同为」**。id / 目标分类不存在 → `missing`；`toIndex` 超出各情形值域 → `invalid`。
  - 目标分类 = 条目当前分类 → 同分类重排语义（含幂等：**目标序位 = 现位** → ok、状态不变）；目标分类 ≠ 当前分类 → 跨分类移动语义（成功返回新状态，沿既有变更函数返回形态）。
  - 跨分类落位：目标分类为空 → 该条目成为其唯一条目；落在自己所在分类 → 等同同分类重排（分类不变、含幂等、不产生分类变更）；`drag` 记录须带来源分类 id（`pointerdown` 时取 `item.closest('[data-cat-id]')` 或等价来源）——「落点分类 = 来源分类」这一分支的判定前提。
  - 与 `app:update` 换分类（#5）的语义分工：`updateApp` 只改 `categoryId`、不控落位（编辑浮层路径，落数组末尾）；`reorderApp` 控落位（拖动路径）——两者不合并，避免编辑被拖动的落位语义污染。
- IPC：复用 `app:reorder`（#14，决策 #36）→ `{ok:true, state, warning?}`，warning 语义同 3.1（落盘失败 = 内存态先生效）。移动后 renderer 按返回的 state 重渲染，并把活动标签切到目标分类（见下「交互」第 4 条）。
- 交互（决策 #25，pointer 事件自绘）：`pointerdown`（左键）于 `.item` 记起点；移动超过阈值 4px 进入拖动态——被拖条目的原位节点变半透明（占位），clone 影随光标（`position: fixed`）；占位随光标落点在网格内滑动预览落点位置。未超阈值松手 = 普通单击（启动路径不变）；拖动态下抑制 click 启动（沿「吞点击」惯例）。
- 落点判定（三级，自上而下）：① 指针在**分类标签**（`.tab`）矩形内 → 跨分类移动，落点分类 = 该标签的 `data-cat-id`，`toIndex` 按来源分类分流：落点分类 = 来源分类 → 送「该分类条目数 - 1」；落点分类 ≠ 来源分类（他类或空分类）→ 送「目标分类当前条目数」（空分类 = 0）。两者均为追加末尾（决策 #37）；② 指针在**内容区网格**内 → 目标分类 = 当前活动分类，`toIndex` = 占位最终序位；③ 其余（顶栏 / 标签栏空白处 / 「＋ 新建分类」/ 空态占位 / 面板外）→ 取消（顺序与分类均不变、无 IPC）。
- 拖动中经过分类标签栏**不切标签**（F2.6 / 4.15 抑制③不动）：`reordering` 标记已使 `hoverSuppressed()` 成立，标签栏 mouseover 不落计时；本次新增的「标签落点判定」只读标签矩形与 `data-cat-id`，不调用 `switchCategory`——拖动全程活动标签不变。
- 跨分类移动成功后的视图：renderer 收到新 state → 活动标签置为目标分类（条目已不在原分类，留在原分类会看到它消失而无反馈；AC-20「条目移入该分类」要求结果可见）→ 整面板重渲染；`save_failed` → warning 语义（新分类与顺序内存态生效 + toast「保存失败」，下次变更重试）。
- 失败与边界：落点分类不存在（标签随重渲染重建的竞态）/ `missing` → 走既有 `toastForCode` 映射（`missing` → 「文件不存在」，4.11 文案表）并保留旧顺序与旧分类；`invalid` → console 留痕、保留旧顺序与旧分类（4.11 固定文案表无 reorder 专属文案，按「不发明文案」纪律不新增——补条目留台账后续批）；拖动中窗口 blur → 取消（防御）；单实例单窗口无并发写（4.10）→ 拖动中条目不会被并发改动；拖动态下不打开条目菜单 / 行内确认（右键菜单与拖动互斥）。
- 与抑制的关系：拖动态置「排序中」标记——F1.6 抑制③（鼠标离开延迟隐藏不启动）与 F2.6 抑制（悬停切标签不触发）均读该标记；拖动结束（含取消）复位；复位时指针已在面板外 → 按抑制解除收尾补起 300ms 隐藏计时（4.5）。
- 与 4.7 拖拽添加的事件面区分：外部 .exe / .lnk 拖入走 HTML5 `dragover` / `drop`（`dataTransfer.files` 非空 → 添加流程），内部排序走 pointer 事件（不产生 drag 事件）；drop 处按 `files.length` 分流——同一 drop 面互不误触。条目图标 `draggable=false`（ui.js 现状）维持，不引入 HTML5 拖放。

### 4.16 快捷方式自愈：启动 + 图标（F3.9 / F3.10 / AC-22 / AC-24）

方案（共享字段 → 采集时机 → 启动选源 → 图标选源 → 存量迁移）：

- 字段：`apps[]` 条目可选字段 `realPath`（字符串 | `null`，缺省 `null`）——仅 .lnk 条目登记，语义 = 「添加时该快捷方式解析出的真实程序位置」（4.10）。启动与图标两条自愈链只读该字段，不改写 `entry.path`。
- 采集时机 = **添加时采集**（决策 #38）：`app:create`（#4）落库前，条目为 .lnk 即解析一次，`target` 非空 → `path.resolve(target)` 随条目写入。添加时刻解析成功率最高；启动 / 取图热路径不回写数据。
- 存量迁移（决策 #39）：启动载入后，main 对「`realPath` 为 null 且 `path` 为 .lnk」的存量条目补登记。补到任一 → 落盘一次；解析失败 → 保持 null；失败只记 console，不打断启动。
- 启动选源（launcher.js，4.9）：① `entry.path` 文件存在 → 启动原路径；② 原路径不存在、条目为 .lnk、`realPath` 非空且文件存在 → 启动 `realPath`；③ 否则按 F4.3 返回既有失败文案。该链不因 F3.10 改动。
- 图标 IPC #8 契约不变：renderer 仍只传 `{id}`；main 用 id 取完整条目后调用 `getIconDataUrl(entry)`。`realPath` 不因图标链新增暴露面——#1 `state:load` 的 apps 本就含 `realPath`（v1.4 起），#8 入参仍只 `{id}`、不新增通道。

**图标候选源判据（钉死）**：`icons.js` 负责文件存在性与 `shell.readShortcutLink` 探测；`icon-fallback.js` 的纯函数 `pickIconSource(entry, observations)` 只按已给事实返回分支与来源路径，不 import Electron / fs。

| 条目与观测 | `realPath` | 返回分支 | 实际取图来源 |
|---|---|---|---|
| 非 .lnk 条目 | 任意 | `direct` | `entry.path`；既有 .exe 链 |
| .lnk 路径存在，且解析得到非空 target | 任意 | `shortcutTarget` | 解析出的 target；既有 .lnk 链 |
| .lnk 路径存在，但解析抛错或 target 为空 | 非空 | `registeredRealPath` | `entry.realPath` |
| .lnk 路径不存在 | 非空 | `registeredRealPath` | `entry.realPath`；不再尝试解析失效路径 |
| 上两种失效情形 | null / 空串 | `originalFallback` | 无新增来源；直接维持原路径的平台结果 / null |

- 本节「`realPath` 非空」只指条目已有非空登记值，不以 `fs.existsSync(realPath)` 作为选源门槛。真实程序文件不存在、平台取图为空 / 通用、直读失败，统一由 4.8 来源链判定为取不到，再落回既有表现。
- .lnk 路径存在且能解析出 target 时，即使 target 文件随后不存在，也仍走既有 `shortcutTarget` 分支；F3.10 不用历史 `realPath` 覆盖一个仍可解析的快捷方式。
- 图标结果收口由纯函数 `settleIconResult(branch, sourceResult, originalPlatformDataUrl)` 完成：`registeredRealPath` 仅在来源链产出真图时替换；否则返回原 .lnk 平台结果 / null。其余分支严格保持 4.8 既有降级顺序。
- 参照物全失效口径（沿 4.8「判定整体不触发」）：来源平台结果不可验证，`settleIconResult` 各分支一律结算回原条目平台结果 / null，不把不可验证的平台结果当真图替换（direct 分支的保留值即第③级，同义重合）；平台结果为空（isEmpty）的触发判定不依赖参照物——空结果仍执行直读，直读产出真图时按各分支既有降级顺序结算。
- 嵌套与失效边界：`realPath` 若本身为 .lnk，只作为单层来源交给 4.8，不再次解析下一层；启动仍由 `shell.openPath` 交给系统处理。解析失败不新增提示，不自动重建快捷方式。
- 编辑与删除联动：`app:update`（#5）不换路径，`realPath` 随条目不变；条目删除（#6）随条目移除，无残留。快捷方式移动后重新添加，仍按 4.7 规范化路径判重；新路径与旧条目路径不同则可并存。

### 4.17 面板顶栏图标（F7.3 / AC-23）

方案（来源 → 下发 → 显示 → dev/prod 统一）：

- 来源 = **运行时读本应用 exe 图标**（决策 #41，单一源）：main 侧 `app.getFileIcon(process.execPath, { size: 'large' })`（Windows large = 32px，由 renderer 按 20×20 显示，见下）→ `toDataURL()` 经 IPC #18 下发。
- 理由：F7.3 要求「与 F7.2 同源的同一份图标、不另存副本」——`process.execPath` 即应用本体 exe，其图标正是 electron-builder 由 `build/icon.ico` 写入的那一档（`win.icon` 编译进 exe 资源）。故「不另存副本」在两态下同时成立：不新增资产文件、不内嵌第二份 base64、不改打包配置。
- dev / prod 路径统一（关键）：**安装运行不读 `build/icon.ico`**——该文件是构建期输入，`electron-builder.yml` 的 `files` 白名单只含 `src/**/*` + `package.json`，打包后 app.asar 内没有它（4.12），安装态只能从 exe 取；开发态仍读源码目录里的那**同一份**文件（`app.getAppPath()` 下 `build/icon.ico`）——两态读的是同一源的不同载体（exe 内嵌档 / 源文件），不是两份副本。
  - 判支：`app.isPackaged` 为真 → `app.getFileIcon(process.execPath)`；为假 → `nativeImage.createFromPath(<appPath>/build/icon.ico)`。`process.execPath` 在开发态是 electron.exe（Electron 默认图标），故开发态必须走后者，否则 AC-23「开发运行也显示」不成立。
  - 开发态兜底：`.ico` 读取失败 / 文件缺失 / `nativeImage` 结果 `isEmpty` → 回落 `app.getFileIcon(process.execPath)`（Electron 默认图标，行为退化但不空白）；ICO 容器七档的解码行为属实现期实测项（十三节第 15 点）。
  - 两态分支收敛在 main 一个函数内（`getAppIconDataUrl()`）：renderer 只调 `api.getAppIcon()`，不感知路径差异。
  - 尺寸统一：prod 取 `large` 档（32px）、dev 取 ICO 内一档（首档或指定档），源图在 renderer 侧按 CSS 20×20 定尺显示（`width/height: 20px`），不要求两态源图同尺寸。
- 下发：新增 IPC #18 `appIcon:get`（无入参、只读），main 侧会话内缓存（首次构造后复用，与 4.8 图标缓存同形态）；返回 `{dataUrl: string | null}`，`null` → renderer 隐藏顶栏 `<img>`（不占位、不留破图）。preload 面 `getAppIcon()`（3.3）。
- 显示位置与尺寸：顶栏左端、标题「速启」之前，20×20（顶栏高 46px、标题 14px/600——取 20px 与标题视觉齐平且不压行高）；`index.html` 顶栏增 `<img id="app-icon" class="topbar-icon" alt="">`（`src` 由 renderer 运行时写入，不内联 dataUrl——CSP 与文档体积）；样式新增 `.topbar-icon`（20×20、`display:none` 直到拿到 dataUrl 再显示，`margin-right: 8px`），**不复用条目图标的 32px 样式类**（尺寸与语义不同面）。
- CSP：`img-src 'self' data:` 已含 `data:` → dataUrl 放行，无需改 CSP（2.3 第 3 条）。
- 失败与边界：图标取不到（资产缺失 / 提取失败）→ 返回 null、renderer 隐藏该 `<img>`，顶栏退化为现状布局（不报错、不 toast）；窗口重建（不销毁）时图标已随首次渲染落地，不重取。


## 五、依赖与选型

| 类别 | 项 | 版本 / 结论 | 理由 |
|---|---|---|---|
| 运行时依赖 | （无） | — | 全部能力用 Electron 内置 API；零第三方运行时包 |
| 开发依赖 | electron | 实测最新 44.5.1（2026-10-06；安装时以最新稳定为准，实际版本登记进实施记录） | 平台已定；需 ≥32（webUtils 与 File.path 移除后的现行路径） |
| 开发依赖 | electron-builder | 实测最新 26.15.3 | F5 打包；NSIS 目标内置（见 4.12） |

- 模块制式：package.json `"type": "module"`——main 侧 ESM（Electron ≥28 支持）；沙箱预加载必须 CJS → `preload.cjs`；store / catalog 为 ESM 纯模块（`node --test` 可直跑）。
  - renderer 用经典脚本（`<script src>`，非 module——`file://` 下 module 脚本被 Chromium CORS 整体拦截，实现期实测）；`ui.js` 经 `window.SuqiUI`、`components.js` 经 `window.SuqiComponents` 暴露，脚本顺序 ui.js → components.js → renderer.js。
- 被拒的第三方（逐条）：
  - 图标提取库（如 extract-file-icon 类）——v1.1 复核维持：`app.getFileIcon` + PowerShell 直读（4.8）已覆盖 exe / lnk 人工样本，无必要引入运行时依赖。
  - UI 框架（React / Vue）——面板为单页静态 UI，原生 DOM 足够；引入即增加运行时依赖与构建链。
  - 自启库（如 auto-launch 类）——`app.setLoginItemSettings` 即平台原生能力（4.13）。
  - 打包替代：electron-forge（Squirrel.Windows 不支持自选安装目录）；electron-packager（不产出安装器）；手写 NSIS / Inno Setup（可控但维护成本高，需求只要求一条命令出安装包）。
  - 数据存储替代：SQLite / leveldb（重）；localStorage（无持久保证，且在 renderer 侧违反安全基线）。
- v1.1 依赖注记：直读兜底（4.8）使用 Windows 自带 PowerShell 5.1（系统组件，非第三方包）；运行时依赖保持零第三方。
- 环境注记（实测）：默认 npm registry 不可达 → 用 `--registry=https://registry.npmmirror.com`；二进制下载镜像见 4.12。

## 十一、边界（设计层面不做）

- 需求边界照旧：无搜索、无扫描收录、无 UWP / 商店应用、无云同步 / 账号 / 插件、无自定义图标上传、不做代码签名（首装 SmartScreen 提示属预期）。
- 设计层额外不做：不做前端构建链（源码即产物，无 webpack / vite）；不做自动更新；不做多语言（仅中文）；不做置顶（条目顺序自 v1.3 起支持拖动调整，跨分类移动自 v1.4 起放开，4.15）；不做面板尺寸记忆；不做数据文件的多版本迁移框架（v1 仅归一化 + 备份策略）。
- v1.1 额外不做（用户裁定）：不做「通用图 → 占位块」替换（方案 B = 平台返回通用图时弃用该图、改以占位块显示；用户裁定排除）；不做条目自定义图标功能（图标恒取程序自带图标，见 F3.2；与应用图标 4.12 无关）；不深挖 getFileIcon 失灵根因（不改 Electron / 不上溯 Chromium 侧）。
- v1.2 额外不做（用户裁定）：默认分类的不可删除语义不变；不做分类（标签）排序；不做更换默认分类（id 恒为 `uncategorized`）；不做名称唯一性约束（重名允许恒成立）。
- v1.3 额外不做：不做分类（标签）排序与置顶（沿 v1.2 边界）；不做快捷键「恢复默认」专门入口（重录默认组合即回默认）；不做组合冲突预检测（以注册成败为准）；不做录制窗位置记忆。
- v1.3.1 额外不做：不做 IME 候选窗 / 输入法宿主的定位与样式控制；不扩展 F1.6 抑制四项（组字中真移出照旧约 300ms 隐藏）；不做多输入法兼容矩阵（以主流中文 IME 为验收面）；录制窗（无文本输入）不纳入组字守卫。
- v1.3.2 额外不做：不做托盘图标的运行时主题自适应（单版形态在两种托盘底色下均可辨 = F7.1 的设计要求）；不做图标形态 / 配色的用户自定义；不做图标生成器入工程构建链（`npm run dist` 不调用它，见 6.5）。
- v1.4 额外不做：不做拖到标签上的落位顺序选择（标签落点按「追加到目标分类末尾」定序，见 4.15 / 决策 #37）；不做跨分类移动后的 toast 反馈（结果由活动标签切换与内容区重渲染呈现）；不做嵌套 .lnk 的递归下钻解析（`realPath` 记一层即止，沿 4.8 既有边界）；不做「快捷方式已失效」专属提示（沿用 4.11 固定文案表）；不做顶栏图标的点击行为与尺寸自适应（20×20 定尺、纯展示）。
- v1.5 额外不做：不改写条目 path、不改存储结构 / `DATA_VERSION`；不做条目自定义图标、IconLocation 检测或嵌套 .lnk 递归；不新增文案 / 提示；不升 package version、不打包、不碰 dist/。

## 十二、UI / 交互决策（全部已落地）
